What is End-to-End Encryption?

End-to-end encryption (E2EE) means your messages are encrypted on your device and can only be decrypted on the recipient's device. The encryption keys never leave your devices — so nobody in between, including Kora's servers, your internet provider, or anyone else, can read your messages.

Not even we can read your messages. We store encrypted copies for delivery, but we don't hold the decryption keys. If a government asked us for your messages, we could only hand over encrypted ciphertext — unreadable to everyone except you and your recipient.

Our Encryption Protocol

Kora uses a modern Double Ratchet encryption protocol — one of the most trusted cryptographic designs for secure messaging. It's built on industry-standard, independently audited cryptography and represents the gold standard for end-to-end encryption.

The Double Ratchet Algorithm

Kora's encryption uses the Double Ratchet algorithm, which combines:

  • X3DH (Extended Triple Diffie-Hellman) — Establishes a shared secret between two parties who have never communicated before
  • Symmetric ratchet — Generates a new encryption key for every single message. Once a key is used, it's destroyed. This provides forward secrecy.
  • Diffie-Hellman ratchet — Periodically mixes in new DH key exchanges to provide post-compromise security — if a key is compromised, future messages are still safe after a DH ratchet step.
// Simplified: every message gets a unique key
message_key = HKDF(chain_key, message_number)
ciphertext = AES-256-GCM(plaintext, message_key)
// After encryption, message_key is destroyed
chain_key = HMAC-SHA256(chain_key, "advance")

  • Each device generates an identity key pair (long-term) and ephemeral key pairs (short-term, rotated regularly)
  • Public keys are shared via Kora's server (which cannot derive the shared secret)
  • The secure handshake protocol combines multiple DH exchanges to create a shared secret
  • Only your device and the recipient's device ever know the shared secret
  • The server only sees public keys — useless without the private keys

Forward Secrecy

Forward secrecy means every message uses a unique encryption key. If an attacker somehow compromises one key, they can only decrypt that one message — not past or future messages.

  • Per-message keys — Each message is encrypted with a new key derived from a ratchet chain
  • Key deletion — After a message is encrypted and the key is used, the key is permanently deleted from memory
  • Post-compromise security — The DH ratchet periodically refreshes the chain. Even if keys are stolen, the next DH ratchet step restores security
  • Session-specific — Each conversation has its own independent key chain. Compromising one conversation doesn't affect others

Safety Numbers

Every chat in Kora has a safety number — a unique fingerprint that identifies the encryption keys of both participants. You can verify your conversation is truly private:

  • Find it: Chat → Info → Encryption → Safety Number
  • Verify: Compare the 60-digit number (or scan the QR code) with the person you're chatting with
  • If they match: Your conversation is completely secure and no one is intercepting it
  • If they don't match: Your conversation may be compromised. Re-establish encryption by clearing the chat's keys.
  • How it works: The safety number is a hash of both participants' identity public keys. A man-in-the-middle attack changes the keys, which changes the safety number.

Pro tip: You don't need to verify every chat — only ones where you discuss extremely sensitive information. Most chats are safe by default.

Group Encryption

Group chats use the Sender Key protocol — an extension of our core encryption protocol for group messaging:

  • Each member gets a sender key that allows them to encrypt messages to the group without individually encrypting for each member
  • Sender keys are distributed via 1-on-1 E2E encrypted channels — so group key distribution is as secure as private messaging
  • When a member leaves, the group ratchets the sender keys — the departed member can't read future messages
  • When a new member joins, they receive sender keys from existing members via E2E encrypted channels
  • Group calls (up to 32) use per-participant E2EE — each participant's audio/video is encrypted with keys only they and the call participants hold

Member changes trigger key rotation. When someone leaves a group, the encryption keys are ratcheted so they can't read future messages — even if they still have the app installed.

Call Encryption

Voice and video calls in Kora are encrypted with WebRTC DTLS-SRTP:

  • DTLS — Datagram Transport Layer Security establishes an encrypted channel between devices
  • SRTP — Secure Real-Time Transport Protocol encrypts the actual audio/video packets
  • P2P when possible — Calls go directly between devices when possible, bypassing servers entirely
  • TURN server fallback — When P2P isn't possible, encrypted media passes through a TURN relay — but the relay can't decrypt it (keys are negotiated end-to-end)
  • Group calls — Use a Selective Forwarding Unit (SFU) with per-participant E2EE. The SFU forwards encrypted packets but cannot read them

Call content never passes through our servers in readable form. Even when using TURN/SFU relays, the media is encrypted end-to-end and the relay only forwards opaque packets.

Media Encryption

Photos, videos, documents, and voice notes are encrypted before they leave your device:

  • AES-256-GCM — Media is encrypted with a random symmetric key generated on your device
  • Secure key exchange — The symmetric key is shared with the recipient using our Double Ratchet protocol (same as text messages)
  • Encrypted upload — The encrypted media is uploaded to our servers, but we only see ciphertext
  • Encrypted download — The recipient downloads the ciphertext and decrypts it locally with their key
  • Auto-delete — Encrypted media is deleted from servers after 90 days (or immediately if the message is deleted)

AI & E2EE Privacy

Kora AI is designed to preserve your E2E encryption:

  • Voice translation — Speech-to-text and translation happen on-device using ML Kit / CoreML. Your voice never leaves your phone, so E2EE is never broken.
  • Voice synthesis — Text-to-speech uses mathematical voice vectors generated locally. No cloud API processes your plaintext.
  • AI chat assistant — When you ask Kora AI a question, only your specific query is sent to the cloud for processing. Your other messages are not shared.
  • No AI training — We never use your conversations, voice data, or AI queries to train any AI model.
  • No data retention — Cloud AI queries are processed in real-time and not stored after generating a response.

On-device AI is the key. By processing voice translation and synthesis locally, your plaintext never touches a server — E2EE is maintained end-to-end.

How to Verify Your Encryption

You can verify that your conversations are truly end-to-end encrypted:

  • Check the lock icon — Every E2E encrypted chat shows a lock icon in the chat header
  • Check safety numbers — Chat → Info → Encryption → Safety Number. Compare with your contact.
  • Scan QR code — If you're in the same room, scan each other's QR code for instant verification
  • Encryption notification — Kora notifies you when a chat's encryption keys change (e.g., if the person got a new phone)
